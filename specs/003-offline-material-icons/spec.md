# Feature Specification: 폐쇄망 대응 — 아이콘 폰트 자체 호스팅

**Feature Branch**: `003-offline-material-icons`

**Created**: 2026-10-07

**Status**: Draft

**Input**: User description: "실 운영 환경이 폐쇄망이므로 외부 자원 없이 저장소 내 자체 호스팅 될 수 있게 변경해줘."

**근거**: 헌법 v1.2.0 원칙 VII(폐쇄망 운영: 외부 CDN·외부 접속 의존 금지). spec 002(WebSocket 화면 갱신)와
목적이 달라 별도 spec 으로 분리한다.

## 배경 및 확정된 사실

- 운영 환경은 폐쇄망이다. 화면이 외부 주소에서 자원을 받아 오면 운영 중에 표시되지 않는다.
- 저장소(`quartz-manager-frontend`) 전수 확인 결과(2026-10-07), 화면이 **자동으로** 외부에서 가져오는 자원은
  **아이콘 폰트(Material Icons) 하나뿐**이다. 나머지(Roboto 폰트, 스크립트, 이미지)는 이미 저장소·번들에 포함되어
  있거나 주석 처리, 또는 문자열일 뿐이다.
- 이 아이콘 폰트는 화면의 두 곳에서 쓰인다: 상단 헤더의 메뉴 버튼, 트리거 설정 화면의 날짜 선택 버튼 2개.
  폐쇄망에서는 아이콘 대신 글자(`menu`, `event`)가 그대로 보인다.
- 같은 외부 주소 때문에 화면 빌드도 빌드 중에 외부 접속을 시도하며, 사설 인증서 환경에서는 빌드가 실패한다
  (`self-signed certificate in certificate chain`).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 폐쇄망 운영 화면에서 아이콘이 정상 표시 (Priority: P1)

운영자가 인터넷이 차단된 폐쇄망에서 관리 콘솔을 열면, 헤더의 메뉴 버튼과 트리거 설정 화면의 날짜 선택 버튼이
글자가 아닌 **아이콘 모양**으로 표시된다.

**Why this priority**: 운영 환경에서 실제로 보이는 결함이며, 이 변경의 존재 이유다.

**Independent Test**: 외부 인터넷을 차단한 환경(또는 브라우저에서 외부 호스트 요청을 차단)에서 화면을 열고,
아이콘 위치 2곳이 아이콘으로 보이는지, 외부 호스트로 나가는 요청이 없는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 외부 인터넷이 차단된 환경, **When** 관리 콘솔 화면을 열면, **Then** 헤더 메뉴 버튼이 글자 `menu`
   가 아닌 아이콘으로 표시된다.
2. **Given** 외부 인터넷이 차단된 환경, **When** 트리거 설정 화면의 날짜 선택 버튼을 보면, **Then** 글자
   `event`가 아닌 아이콘으로 표시된다.
3. **Given** 화면을 로드하는 동안, **When** 브라우저의 네트워크 요청을 확인하면, **Then** 외부 호스트로 가는
   요청이 하나도 없다.

---

### User Story 2 - 외부 접속 없이 화면 빌드 성공 (Priority: P1)

개발자가 외부 접속이 불가능하거나 사설 인증서가 적용된 환경에서 화면을 빌드해도, 외부 자원 접속 때문에 실패하지
않고 빌드가 성공한다. 빌드 결과물에는 외부 폰트·CDN 주소를 자동으로 가져오는 참조가 남지 않는다.

**Why this priority**: 현재 Windows 개발 PC에서 빌드가 이 문제로 실패하고 있고, 빌드 결과물이 폐쇄망 운영에
그대로 배포되므로 결과물 자체가 외부 의존이 없어야 한다.

**Independent Test**: 외부 접속이 차단된 상태에서 화면 빌드를 실행해 성공하는지, 결과물에 외부 폰트·CDN 주소의
자동 로드 참조가 0건인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 외부 인터넷이 차단되었거나 사설 인증서 때문에 외부 HTTPS 접속이 실패하는 환경, **When** 화면
   빌드를 실행하면, **Then** 외부 자원 접속 오류 없이 빌드가 성공한다.
2. **Given** 빌드가 성공한 상태, **When** 결과물에서 외부 폰트·CDN 주소(`googleapis`, `gstatic`, `fontawesome`)의
   자동 로드 참조를 검색하면, **Then** 0건이다.
3. **Given** 외부 접속이 가능한 환경, **When** 같은 빌드를 실행하면, **Then** 동일하게 성공하고 결과가 같다.

---

### User Story 3 - 기존 화면에 부작용 없음 (Priority: P2)

이 변경으로 아이콘 이외의 화면 요소(글꼴, 색상, 레이아웃, 동작)와 spec 002 의 화면 갱신 기능은 달라지지
않는다. 아이콘의 크기와 정렬도 기존과 같다.

**Why this priority**: 오픈소스 원본 구조를 유지하는 것이 프로젝트의 원칙이다(헌법 III).

**Independent Test**: 변경 전후 같은 화면을 비교해 아이콘 이외의 차이가 없는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 변경 후 화면, **When** 헤더와 트리거 설정 화면을 변경 전과 비교하면, **Then** 아이콘 모양 이외의
   차이가 없다(크기·정렬 포함).
2. **Given** spec 002 의 화면 갱신 기능, **When** 작업을 실행해 시각·진행 정보가 갱신되는지 확인하면,
   **Then** 변경 전과 동일하게 동작한다.

---

### Edge Cases

- 개발자 PC처럼 외부 접속이 가능한 환경에서도 아이콘 표시와 빌드는 동일해야 한다(환경에 따라 달라지면 안 된다).
- 콘솔이 웹자 경로(`/quartz-manager-ui/`) 하위나 프록시 경로 아래에서 서비스될 때에도 아이콘 자원의 주소가
  올바르게 풀려야 한다(파비콘과 같은 상대 경로 방식).
- 아이콘 자원 파일이 누락되거나 경로가 어긋나면 글자가 그대로 보이므로, 빌드 결과물에 자원이 포함되었는지를
  검증 단계에서 확인해야 한다.
- 폰트 자원은 특정 버전으로 고정된다. 원본에서 아이콘이 추가되어도 반영되지 않으며, 현재 화면이 쓰는 아이콘은
  모두 포함되어 있어야 한다.
- 구형 브라우저에서 해당 폰트 형식을 지원하지 않는 경우는 범위 밖이다(Assumptions 참조).
- 외부 주소가 남아 있어도 자동으로 접속하지 않는 항목(클릭해야 이동하는 GitHub 링크, 링크 미리보기 메타 정보,
  주석·라이선스 문구, SVG 네임스페이스)은 변경 대상이 아니다.

## Requirements *(mandatory)*

### Functional Requirements

**기능 요구사항**

- **FR-001**: 아이콘 폰트에 필요한 자원(폰트 파일과 이를 적용하는 스타일 정의)은 저장소 안에 포함되어야 하며,
  화면은 외부 주소 대신 이 자원을 사용해야 한다(MUST).
- **FR-002**: 헤더의 메뉴 버튼과 트리거 설정 화면의 날짜 선택 버튼 2개는 외부 접속 없이 아이콘 모양으로
  표시되어야 한다(MUST).
- **FR-003**: 화면 빌드는 외부 접속 없이 성공해야 한다(MUST). 외부 HTTPS 접속이 사설 인증서 때문에 실패하는
  환경에서도 성공해야 한다(MUST).
- **FR-004**: 빌드 결과물에는 외부 폰트·CDN 주소(`googleapis`, `gstatic`, `fontawesome`)를 자동으로 가져오는
  참조가 없어야 한다(MUST). 화면을 로드할 때 외부 호스트로 가는 요청이 없어야 한다(MUST).
- **FR-005**: 폰트 자원의 출처, 버전, 라이선스(Apache-2.0)를 확인할 수 있게 기록해야 한다(MUST).
- **FR-006**: 변경 후에도 아이콘의 크기, 정렬, 색상 등 표시는 기존과 같아야 한다(MUST).

**변경 범위(최소 수정) 요구사항 — 헌법 원칙 III·VII**

- **FR-007**: 코드·자원 변경은 FR-001~FR-006 을 직접 구현하는 데 필요한 것으로 **한정**한다(MUST). 변경 대상은
  다음 3가지로 고정한다.
  1. 아이콘 폰트 파일 추가(`src/assets/fonts/material-icons/` 아래)
  2. 아이콘 폰트 스타일 정의 파일 추가(같은 폴더)
  3. `src/index.html` 에서 외부 아이콘 폰트 링크 1줄을 위 스타일 정의 링크로 교체
- **FR-008**: 다음은 변경해서는 안 된다(MUST NOT): `angular.json`, `package.json`/`package-lock.json`, 빌드·테스트
  설정, 컴포넌트·서비스·모델 코드, 기존 스타일(`src/styles.css` 등), Roboto 등 다른 폰트, spec 002 의 변경 파일
  (`manager.component.ts`/`.html`), qssb, nginx 설정.
- **FR-009**: 새로운 외부 자원(CDN 폰트·스크립트·이미지·추적 코드)을 추가해서는 안 된다(MUST NOT). 자동으로
  접속하지 않는 기존 외부 주소(클릭 링크, 메타 정보, 주석)는 변경하지 않는다.
- **FR-010**: 변경한 모든 파일과 근거(헌법 원칙 VII)를 `spec-003-changelog.md`에 변경 파일 목록과 compare
  내용(한글)으로 기록해야 한다(MUST).

### Key Entities *(include if feature involves data)*

- **아이콘 폰트 자원**: 아이콘 글리프를 담은 폰트 파일, 이를 글꼴로 선언하고 아이콘 표시 규칙(크기, 정렬, 글자
  변환 방식)을 정의하는 스타일 정의, 출처·버전·라이선스 정보. 화면 문서에서 한 줄로 연결된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 외부 인터넷이 차단된 환경에서 아이콘 위치 3곳(헤더 메뉴 버튼 1, 날짜 선택 버튼 2) 모두 아이콘
  모양으로 표시되고, 글자(`menu`, `event`)가 노출되는 경우가 0건이다.
- **SC-002**: 화면을 로드하는 동안 브라우저가 보내는 요청 중 외부 호스트로 가는 요청이 0건이다.
- **SC-003**: 외부 접속이 차단되었거나 사설 인증서로 외부 HTTPS 접속이 실패하는 환경에서 화면 빌드가 100%
  성공한다(외부 접속 오류로 인한 실패 0건).
- **SC-004**: 빌드 결과물에서 외부 폰트·CDN 주소(`googleapis`, `gstatic`, `fontawesome`)의 자동 로드 참조가
  0건이다.
- **SC-005**: 변경된 파일은 FR-007 의 3가지와 changelog 뿐이며, FR-008 금지 항목 파일의 변경이 0건이다.
- **SC-006**: 아이콘 이외의 화면 요소와 spec 002 의 화면 갱신 기능이 변경 전과 동일하게 동작한다(차이 0건).

## Assumptions

- 운영 환경은 폐쇄망이며 사용자 브라우저는 최신 브라우저(woff2 폰트 지원)이다. 구형 브라우저 지원은 범위 밖이다.
- 화면이 쓰는 아이콘은 현재 헤더 메뉴와 날짜 선택 2곳이며, 폰트 전체를 포함하므로 같은 계열의 다른 아이콘도
  표시된다.
- 자체 호스팅할 폰트는 현재 화면이 사용하는 것과 같은 버전(Google 제공 `v145`)을 그대로 쓴다. 폰트의
  라이선스는 Apache-2.0 이라 저장소에 포함해 배포할 수 있다.
- 이 spec 은 화면 자산(폰트)만 다룬다. 개발 PC 의 외부 접속 제약(Node/npm/Maven 플러그인 다운로드)은 별개 문제이며
  `buildAndPatch.md` 의 로컬 저장소 캐시·`node_modules` 반입 절차로 다룬다(헌법 원칙 VII).
- spec 002 와 변경 파일이 겹치지 않는다(002 는 `manager.component.*`, 003 은 `index.html` 과 신규 자원). 두 spec 은
  독립적으로 구현·검증할 수 있다.
- 구현 시 폰트 파일은 인터넷이 되는 환경에서 한 번 받아 저장소에 포함하며, 이후 빌드·운영에서는 외부 접속이 필요
  없다.
